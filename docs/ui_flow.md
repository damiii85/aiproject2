# 화면 흐름

1. 시작 배너 → 대구 도심 통합상권 / 수성못 / 삼덕동 / 동대구역 / 칠곡3지구 선택 → 즉시 채팅.
2. 도심 카드에 동성로·대구역·반월당을 구성 지역으로 표시. 검색어에 세부 지역명을 넣어도 통합 카드가 검색됨.
3. 최근 대화 / 채팅·시각화 / 지역 지도·통계의 3열 배치(16:54:30). 헤더 아래 가용 높이를 사용하며 최근 대화 목록, 메시지 목록, 분석 패널은 각각 독립적으로 스크롤한다. 채팅 제목과 추천 질문·입력창은 메시지 스크롤 밖에 둔다.
4. 지역 전체 집계 또는 사용자가 지정한 반경을 카드·도넛·업종 구성 그래프에 동일하게 적용. 기준점과 범위를 표시.
5. 도심 전체 지도는 세 수집 원의 합집합, 반경 질문 지도는 해당 기준점과 요청 반경 표시. 후보 핀·주소 추천·순위는 제공하지 않음.
6. 지정 PDF는 `상권보고서.pdf`. 도심 PDF 값은 세부 구역별로 표시하며 합계 값을 만들지 않음. 출처는 파일명·페이지·기준연월 표시.
7. PDF의 동대구역·칠곡3지구 경계는 미확정. API 반경 원을 PDF 상권 경계로 표현하지 않음.
8. 이전 보고서 응답이 남지 않도록 개정판 전환 시 브라우저 세션을 새 버전으로 초기화. 이후 대화는 권역별로 세션 안에 보관하며 영구 저장하지 않음.

지도·분석 카드·다운로드는 같은 요청 범위의 집계를 사용한다. 주변 개별 상가명·주소·좌표 목록은 공개하지 않는다. 주소 분석에서는 사용자가 입력한 기준 주소 및 계산에 사용한 등록 좌표·위치 출처를 포함한다. 임대료·업종별 매출은 알 수 없다고 안내한다.

주소를 명시하면 API 수집본의 도로명+건물번호 또는 지번과 일치하는 등록 좌표를 사용한다. 여러 좌표는 기존 주소 좌표 검증(중앙값 및 편차 검사)을 적용한다. 좌표가 확인되지 않거나 같은 도로명·번호가 여러 구에 있으면 재입력을 요청하고 지역 기점으로 대체하지 않는다. 별도 지오코딩 API 호출은 추가하지 않았다.
예: `대구광역시 중구 중앙대로 412-21 100m 카페` → `50m 이내는?`은 같은 주소로 재계산. 주소만 바꾸면 직전 반경을 유지한다. 첫 주소에 반경이 없으면 200m를 기본으로 사용하며 답변에 범위를 명시한다. `지역 전체` 또는 `상권 기준점`으로 주소 기준을 해제한다. 요청 원 전체가 수집 범위 안에 없으면 전체 개수를 추측하지 않는다.

실행: `python -m streamlit run app.py`.
브라우저 검사: `python scripts/check_ui_browser.py --url http://localhost:8501`.

레이아웃 검사: `python scripts/check_layout_browser.py --url http://localhost:8501`.
화면 너비 1200px 이상은 세 패널을 표시한다. 900~1199px에서는 채팅·분석을 표시하고 '대화 목록'으로 좌측 목록에 접근한다. 900px 미만에서는 '채팅 / 분석 / 대화 목록'을 전환한다. 패널 전환으로 대화나 분석 상태를 초기화하지 않는다.
사용자 메시지는 우측, AI 메시지는 좌측에 배치한다. 기존 요약 카드·출처·상세 내용 펼치기와 우측 지도·통계·차트·다운로드를 유지한다. 이번 레이아웃 변경은 세션 버전을 올리거나 기존 대화를 초기화하지 않는다.
