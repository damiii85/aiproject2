# 대구 스팟 선택 파일럿

## 사용자 흐름

대구 → 동성로·수성못·동대구역·칠곡3지구 선택 → 채팅으로 도로명 주소와 업종 입력 → 수집본 전체에서 주변 점포 집계 → 근거와 한계가 포함된 리포트 제공.

```bash
source venv/Scripts/activate
streamlit run app.py
```

주소와 업종은 한 번에 입력하거나 차례로 입력할 수 있다. 업종은 GMS로 자연어를 해석한 뒤 해당 CSV의 실제 대·중·소분류 값인지 검증한다. 음식점에 한정하지 않는다. 스팟을 바꾸면 대화·주소·업종·리포트도 스팟별로 분리된다. 저장은 현재 Streamlit 세션 범위이며 영구 대화 저장은 후속 작업이다.

주소는 수집된 상가의 도로명+건물번호와 대조한다. 일치하는 건물의 상가 좌표 중앙값을 대표 위치로 사용하며 지도에 표시한다. 미확인 주소를 스팟 중심점으로 대체하지 않는다. 수집본에 없는 주소·지번 주소는 도로명으로 다시 입력하거나 지도에서 확인한 위경도를 직접 지정해야 한다. 범용 주소 지오코딩 API는 아직 연결하지 않았다.

## 확보 데이터

2026-10-21 API 실제 수집 기준:

| 스팟 | 상가 수 | 소분류 수 | 중심 위도·경도 | 범위 |
|---|---:|---:|---|---|
| 동성로 | 8,496 | 230 | 35.870, 128.595 | 반경 1km |
| 수성못 | 2,106 | 181 | 35.828, 128.617 | 반경 1km |
| 동대구역 | 3,321 | 211 | 35.879, 128.628 | 반경 1km |
| 칠곡3지구 | 2,359 | 183 | 35.943, 128.563 | 반경 1km |

좌표는 파일럿용 대표 중심점이며 역·관광지의 정확한 기준점이나 공식 상권 경계로 간주하지 않는다. 설정은 `config/daegu_spots.json`에서 관리한다. 업종을 제한하지 않고 반경 내 전체 상가를 수집했다.

- 기존 동성로 원본: `data/raw/dongseongro_stores.csv`와 `collection_metadata.json` 유지.
- 추가 스팟: `data/raw/spots/<spot_id>/stores.csv`, `metadata.json`.
- 가공본: `data/processed/spots/<spot_id>/category_counts.csv`, `summary.json`.
- 전체 비교: `data/processed/spots/overview.csv`, `data/processed/spot_inventory.json`.
- 원본에는 상가 ID·명칭·대중소 업종·주소·위경도 등이 있다. 가공본에는 업종별 점포 수·수집 범위·시점·원문 경로·확보하지 못한 자료와 후속 검색어가 들어 있다.

```bash
python src/collectors/collect_spot_stores.py --spot all
python -m src.services.spot_summary
```

기존 파일은 기본적으로 재사용한다. 갱신하려면 `--refresh`를 지정한다. 기존 동성로 원본 대신 스팟별 폴더에 새 수집본을 저장한다. `PUBLIC_DATA_API_KEY`를 사용하며 추가 키나 라이브러리는 필요 없다.

## 리포트와 제한

상가 수·선택 업종 수·중분류 분포·거리순 경쟁 점포 목록을 전체 CSV에서 계산한다. 여러 업종에 중복 해당하는 상가는 합계에서 한 번만 센다. 반경 원 일부가 수집 범위 밖이면 수집본 내 확인 수치이며 과소 집계 가능하다고 표시한다.

현재 리포트는 CSV 통계 리포트다. GMS는 주소·업종 추출에 사용하며, RAG 문서 해설·LangGraph의 최종 답변 생성은 아직 연결하지 않았다. 새 스팟은 Chroma에 재색인하지 않았으며 기존 `store_metadata` 8,496건은 그대로 유지한다. 기존 RAG 1 CLI는 여전히 동성로 전용이므로 다지역 검색에 바로 사용하지 않는다.

매출·임대료·실제 유동인구와 스팟별 분석 보고서는 미확보로 표시한다. 기존 동성로 지하철 통계를 다른 스팟에 재사용하지 않는다. 등록된 상가 수가 현재 영업 중인 점포 수나 입지의 우열을 의미하지 않는다.

## 추가 자료 확보 순서

탐색 경로와 확인 상태는 `config/spot_report_sources.json`에 정리했다. 포털 메인 URL은 문서 출처로 인용하지 않고, 실제 확보한 문서의 상세 URL을 기록한다.

1. 소상공인365에서 대구 → 각 스팟 영역 → 분석 업종과 기준 시점을 선택한다. 제공되는 보고서·표의 다운로드 가능 여부와 이용 조건을 확인하고, 가능할 경우 원문 URL·분석 영역·기준일과 함께 보관한다. 다운로드 기능의 실제 지원 여부는 로그인 후 확인이 필요하다.
2. 대구 D-데이터허브에서 인구·교통 자료를 찾는다. 시간대·격자·행정동 등 실제 제공 단위를 확인하고, 행정동 수치를 후보지 반경 200m 수치로 바꾸어 표현하지 않는다.
3. 한국부동산원에서 공실·임대 동향 원표 또는 공표보고서를 확보한다. 조사 상권의 경계·표본·분기가 우리 스팟과 같은지 확인한다.
4. 대구시·구청·한국은행 지역본부의 실제 상권·소비 해설 문서를 찾는다. 대구시 공식 기사의 검색 결과 요약에서 ‘2024년 동성로 상권 빅데이터 분석자료’를 인용한 것을 확인했다. 기사 원문 열기는 502 오류로 실패했다. 원 보고서 공개 여부를 확인하거나 해당 기관에 자료 제공을 요청하는 후속 경로로 활용한다. 아직 원 보고서 파일을 확보한 것은 아니다.
5. 최종 확보 문서마다 스팟 ID·기관·제목·상세 URL·공표/수집일·통계 단위·이용조건을 기록한 뒤 RAG 2에 넣는다. 다른 스팟의 수치를 섞지 않도록 지역 필터를 연결해야 한다. 현재 RAG 2 검색어·선별 프롬프트는 법령보다 상권·소비·공실·임대 동향을 우선하도록 수정했다.

## 검증

```bash
python -m unittest discover -s tests -v
```

4개 스팟 실제 수집본의 행 수·고유 ID 검증, 건물번호 정확 일치, 허위 업종·주소 거부, 다중 업종 중복 제거, 범위 이탈 처리, Streamlit 스팟 전환·채팅 리포트·대화 분리를 테스트한다. 실제 GMS로 4개 스팟에서 주소와 카페 업종 추출 후 CSV 집계까지 실행했다. 외부 브라우저에서 지도 타일 표시와 실제 사용자 채팅 전체 경로를 시각적으로 확인한 것은 아니다.
